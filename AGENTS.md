# Commit attribution

- Do not add a `Co-Authored-By` trailer identifying Claude, Anthropic, or any Claude model to any Git commit message.
- Do not add equivalent Claude authorship or "generated by Claude" attribution elsewhere in commit messages.
- Preserve the repository's configured human author and committer identity.
- Apply these rules to new commits, amended commits, and rewritten commits.

# Cadence, tests, history and worktrees

- Follow sections 2, 3, 6 and 7 of `docs/APP_WORKFLOW.md`; they apply to work in this repository too, with this repository's tests in place of an app's. The rest of this file adds what is specific to frost_ui.

# No work logs

- Docs state current rules and API facts. Do not write progress, evidence, acceptance records, test counts, commit ids or stage status into any document, and do not keep backups of removed documents; git and the code are the record.
- Comments and test names describe behaviour. They do not cite stage, batch or audit codes.
- A failing test is fixed or reported on the spot; there is no "pre-existing failure" exception.

# App change requests

- Apps do not edit frost_ui's source, tests or tools. What an app needs from frost_ui arrives as a request in `docs/requests/`; its `README.md` holds the format, the statuses and the maintainer steps.
- Work on requests only in a maintainer session the owner starts. Take every `open` request in that pass unless the owner narrows the scope.
- A default or geometry change reaches every app. Weigh it against a new parameter, and make it only with `--dependents`, a MIGRATION entry, and the owner's confirmation. This takes precedence over the global rule that treats a shared-default change at the origin as part of the fix.
- Do not edit app repositories. At the end, list the apps whose workarounds can now be replaced.

# Checks

- At a checkpoint, run `dart tool/affected_tests.dart <base> --run`, where `<base>` is the previous checkpoint's commit. It analyzes the changed libraries and their direct importers, runs the tests that use what the changed libraries declare, and runs the script test of a changed tool. Add `--consumer <app directory>` for each app whose request or usage the change touches, and `--dependents` only when the change alters a default or geometry that every caller sees.
- Do not run `flutter test` / `dart test` without named test files; the PreToolUse hook in `.claude/settings.json` blocks them, and apps use the same hook script by its absolute path. The tool prints only failures and a summary, so a broad selection (a `--dependents` run usually is one) just runs; it needs no question to the owner.
- The library health gate runs inside `affected_tests.dart`; its spec is `tool/library_health/README.md`. If it reports growth, stop and report it instead of working around it.
- A full run happens only when the owner asks for one, usually before a release: `dart tool/affected_tests.dart --all --run`.
- Screenshots: a frost_ui change needs none, and a full run takes no matrix of images across themes and text sizes. Whether text overflows is checked by tests in code.
